# @transferchecker/sheet-pdf

يحوّل تخطيط الورقة إلى مصدر Typst ثم إلى PDF جاهز للطباعة.

الحزمة **لا تحسب أي إحداثي**. كل موضع يأتي من `@transferchecker/sheet-spec`، فما يُطبع هو حرفياً ما سيقرؤه الماسح.

## لماذا Typst

تحقّقنا بالتشغيل الفعلي: Typst يشكّل العربية بشكل صحيح (وصل الحروف وترتيب RTL) ويضع المحتوى بدقة ملليمترية في آن. مكتبات JavaScript لتوليد PDF لا تفعل الاثنين معاً، وpdf-lib لا يشكّل العربية إطلاقاً. التفاصيل في [`docs/TECH-STACK.md`](../../docs/TECH-STACK.md).

## الاستخدام

```ts
import { layoutSheet, SheetSpecSchema } from '@transferchecker/sheet-spec';
import { renderSheetTypst } from '@transferchecker/sheet-pdf';

const spec = SheetSpecSchema.parse(input);
const result = layoutSheet(spec);
if (result.kind !== 'ok') return result; // overflow, تُعرض للمعلم

const source = renderSheetTypst(result.layout, {
  fonts: ['IBM Plex Sans Arabic', 'IBM Plex Sans'],
  warningLines: ['Print at 100% scale. Do not use Fit to page.'],
});
```

**الكود المطبوع لا يُمرَّر هنا.** التخطيط يحمله في `layout.code` جاهزاً بوحداته وموضعه، لأن عدد وحداته يحدد حجمه المطبوع وحجمه يزيح الترويسة. الهندسة لها مالك واحد، فالمولّد يرسم وحدات تُعطى له ولا يصنع منها شيئاً. النتيجة أن الورقة والكود المطبوع عليها يخرجان من نداء واحد ولا يمكن أن يصفا هندستين.

`renderSheetTypst` دالة خالصة تعيد نصاً. التصريف إلى PDF خطوة منفصلة عند الحافة، حتى يبقى التوليد قابلاً للاختبار بلا ثنائيات.

## عدة أوراق في صفحة واحدة

```ts
const page = planPage('A5', 2); // null إذا كان المقاس لا يقبل هذا العدد
const source = renderSheetTypst(layout, { fonts, warningLines, page });
```

**الأوراق تُرصَّف بمقاسها الحقيقي ولا تُصغَّر أبداً.** تصغير الورقة يصغّر فقاعاتها ومربعاتها الركنية معها، والماسح يقيس بالمليمتر، فالورقة المصغَّرة ورقة لا تُقرأ. لذلك ورقة نصف الصفحة **مصمَّمة بمقاس نصف الصفحة** لا مقصوصة من A4.

| مقاس الورقة      | نسخ الصفحة | صفحة الطباعة |
| ---------------- | ---------- | ------------ |
| `A4` / `LETTER`  | 1          | نفسها        |
| `A5`             | 1 أو 2     | A4 عرضية     |
| `A6`             | 1 أو 4     | A4 طولية     |
| `HALF_LETTER`    | 1 أو 2     | Letter عرضية |
| `QUARTER_LETTER` | 1 أو 4     | Letter طولية |

السعة المقيسة (خمسة خيارات، مع شبكة معرّف وبدونها):

| المقاس | بلا شبكة معرّف | مع شبكة معرّف |
| ------ | -------------- | ------------- |
| `A4`   | 116            | 87            |
| `A5`   | 36             | 18            |
| `A6`   | 10             | **صفر**       |

**ربع الصفحة لا يتسع لشبكة معرّف بأي عدد أسئلة.** ورقة بهذا المقاس تعرّف الطالب بخانة كتابة يدوية، والتخطيط يرجع `overflow` في منطقة `sidebar` إن طُلبت الشبكة، فالحالة تُبلَّغ ولا تُخمَّن.

## درجة السواد

```ts
renderSheetTypst(layout, { fonts, warningLines, theme: themeFor('dark') });
```

الطابعات المكتبية أكثر ما يتفاوت في هذا المسار كله: الملف نفسه يخرج باهتاً من واحدة ومطموساً من التالية. `light` لطابعة تضع حبراً زائداً حتى تنغلق الفقاعة، و`dark` لطابعة باهتة يصعب التصويب على فقاعاتها.

**لا يتغير إلا الحبر. ولا يحرّك أي مستوى فقاعة.** المعلم يعيد الطباعة بأي درجة والأوراق الموزَّعة قبلها وبعدها تُصحَّح على الهندسة نفسها، واختبار يثبت ذلك.

## صيغ التصدير

| الصيغة | تحمل المقاس الحقيقي؟ | الاستخدام                      |
| ------ | -------------------- | ------------------------------ |
| PDF    | **نعم**              | **الطباعة. هذه هي الصيغة.**    |
| SVG    | نعم بعد التصحيح      | معاينة، وبديل طباعة من المتصفح |
| PNG    | **لا**               | معاينة ومشاركة فقط             |

**PDF وحده يحمل مقاس الصفحة الفيزيائي**، وعليه وحده تُطبع الأوراق.

وTypst يكتب أبعاد الـSVG أرقاماً مجردة من النقاط، والمتصفح يقرأ الرقم المجرد بكسلات، فورقة A4 تصل 596 بكسلاً وتُطبع بعرض 157mm بدل 210mm: **كل فقاعة أصغر بالربع، وورقة لا يقرؤها الماسح**. لذلك `withPhysicalSize(svg, paper)` يعيد كتابة الجذر بالمليمتر، **ويرمي استثناءً إن لم يجد ما يصححه** بدل أن يعيد ملفاً يطبع صغيراً بصمت.

**PNG لا تنتجه هذه الحزمة**، لسببين:

1. **مصرّف Typst 0.7.0 لا يخرج PNG إطلاقاً** (PDF وSVG وHTML فقط)، فإنتاجه يستلزم مكتبة ترقيم أصلية جديدة.
2. **الأهم: PNG لا يحمل مقاساً فيزيائياً موثوقاً.** ورقة تُلصق في مستند ثم تُطبع تخرج بمقاس خاطئ، والماسح يفشل أو، وهو أسوأ، يبدو ناجحاً ويصحح خطأً.

فمكان PNG هو طبقة التطبيق حيث يوجد canvas: المتصفح يرسم الـSVG ثم `toBlob('image/png')` بلا أي تبعية، والموبايل عبر Skia الموجود أصلاً في الستاك. **وهو للمعاينة والمشاركة لا للطباعة.** إن أُريد PNG من جهة الخادم فالقرار إضافة مكتبة ترقيم، وهو قرار مفتوح لصاحب المنتج.

## موضع حرف الخيار

الحرف يُطبع **إما داخل فقاعته وإما بجانبها، لا الاثنين**. التخطيط هو من يقرر ذلك: إذا كانت `choiceLabels` فارغة فالحرف داخل الفقاعة، وإلا فلكل حرف موضعه الخاص بجانبها.

الحرف الداخلي يبقى فاتحاً عمداً حتى تقرأ الفقاعة كفراغ عند الماسح. الحرف الخارجي يقع خارج كل منطقة تُعاين، فيُطبع أغمق وأوضح. هذا هو مقابل الوضوح الذي يشتريه المعلم حين يختار `external`.

## الأمان: لماذا كل نص مستخدم يخرج كسلسلة نصية

أسماء القوالب وتسميات الحقول يكتبها المستخدم، وTypst يعتبر `#` بداية كود. لذلك **لا يُكتب أي نص مستخدم في وضع الـmarkup إطلاقاً**، بل يخرج دائماً كسلسلة نصية بين علامتي اقتباس عبر `str()`، فلا يوجد أصلاً مسار يصل به إلى موضع تنفيذ. الاختبارات تغطي هذا باسم قالب عدائي.

## الأوامر

```bash
pnpm test       # وحدات + اختبار تكامل يتحقق أن Typst يقبل المصدر المولَّد
pnpm typecheck
pnpm sample     # يولّد docs/samples (إنجليزي، عربي، تسمية خارجية، نسختان، أربع نسخ، وسواد داكن)
```

مثال مع خطوط:

```bash
pnpm sample ../../docs/samples ../../.fonts
```

## الخطوط

Typst لا يقرأ خطوط النظام هنا، فيجب تمرير مجلد خطوط يحتوي على TTF أو OTF لعائلة IBM Plex. الخطوط ليست في المستودع، وتُجلب عند البناء.

## معايرة الطباعة

قبل اعتماد أي تغيير في `GEOMETRY`: اطبع الورقة بمقياس 100٪ وقس بالمسطرة أن المربعات الركنية 8mm وأن مسافة الفقاعات 6.2mm. تغيير الثوابت يكسر توافق الأوراق المطبوعة سابقاً ويستوجب رفع `SheetSpec.version`.
