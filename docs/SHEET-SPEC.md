# مواصفة تصميم ورقة الإجابة (Sheet Spec v2)

> آخر تحديث: 2026-08-13. المرجع البصري: نمط ZipGrade (صورة مرجعية من المستخدم).
> النماذج البصرية: `docs/mockups/sheet-mockup-en.svg` و `docs/mockups/sheet-mockup-ar.svg`.

## 1) المبدأ الحاكم

الورقة تولَّد من config والماسح يستنتج نفس الإحداثيات من نفس الـconfig.
دالة خالصة واحدة `layout(spec) -> coordinates` تعيش في حزمة `sheet-spec` ويستهلكها الطرفان: مولّد PDF (Typst) ومحرك المسح (core-omr). صفر تخمين.

## 2) مناطق الورقة (A4: 210x297mm، Letter: 216x279mm)

| المنطقة                     | الموقع                            | ملاحظات                              |
| --------------------------- | --------------------------------- | ------------------------------------ |
| مربعات ركنية (fiducials)    | 4 زوايا، 8x8mm، هامش 6mm          | نقاط المرجع للتصحيح المنظوري         |
| شريط التوقيت (timing marks) | الحافة اليسرى، علامة لكل صف أسئلة | تحديد الصف حتى مع انزياح الطباعة     |
| اسم الموقع                  | نص عمودي على الحافة اليسرى أعلى   | نص قابل للتخصيص (branding)           |
| عنوان الاختبار              | نص عمودي على الحافة اليمنى        | من إعداد المستخدم، أي لغة            |
| QR                          | مربع صغير أعلى يمين               | يحمل templateId + version + formCode |
| حقول الترويسة               | شريط أفقي أعلى الورقة             | قابلة للإضافة والحذف والتخصيص        |
| شبكة الأسئلة                | جسم الورقة، 1 إلى 4 أعمدة         | فقاعات بمسافات ثابتة بالمليمتر       |
| شبكة هوية الطالب            | يمين الجسم (اختيارية)             | أعمدة أرقام 0-9                      |
| تحذير الطباعة               | أسفل الورقة                       | «Print at 100% scale»                |

## 3) السكيما (Zod، حزمة sheet-spec)

```ts
// Header fields are fully user-defined: any label, any language,
// handwritten box or bubble grid (e.g. a bubbled name instead of writing).
const HeaderField = z.object({
  id: z.string().min(1).max(24),
  label: z.string().min(1).max(40), // any language, shaped by Typst
  kind: z.enum(['writtenBox', 'bubbleGrid']),
  // bubbleGrid only:
  length: z.number().int().min(1).max(12).optional(), // characters/digits count
  alphabet: z.enum(['digits', 'latin', 'arabic']).optional(),
});

export const SheetSpec = z.object({
  templateId: z.uuid(),
  version: z.literal(2),
  paper: z.enum(['A4', 'LETTER']),
  questions: z.number().int().min(1).max(200),
  choices: z.number().int().min(2).max(6),
  columns: z.number().int().min(1).max(4),
  bubbleLabels: z.enum(['latin', 'arabic']), // A B C D vs Arabic letters
  headerFields: z.array(HeaderField).max(6), // default: name + section + score
  studentId: z
    .object({
      digits: z.number().int().min(2).max(10),
    })
    .nullable(), // null = no student ID grid
  branding: z.string().max(30), // vertical site name text
  title: z.string().max(60), // vertical exam title, any language
  formCode: z.string().regex(/^[A-D]$/),
  bubble: z.object({
    rMm: z.number().min(1.8).max(3.5),
    pitchXMm: z.number().min(5).max(10),
    pitchYMm: z.number().min(6).max(12),
  }),
});
```

## 4) حرية التخصيص (ما يتحكم فيه المعلم)

- عدد الأسئلة (1-200)، عدد الخيارات (2-6)، عدد الأعمدة (1-4).
- حروف الفقاعات: لاتينية (A B C D) أو عربية (أ ب ج د).
- حقول الترويسة بالكامل: إضافة، حذف، إعادة تسمية بأي لغة، وتحويل أي حقل من كتابة يدوية إلى تظليل فقاعات (مثال: الاسم تظليلاً بدل الكتابة).
- شبكة هوية الطالب: اختيارية، عدد خانات 2-10، أو تُستبدل بحقل ترويسة مخصص.
- اسم الموقع وعنوان الاختبار: نص حر.
- أبعاد الفقاعات والمسافات: قيم افتراضية مدروسة وقابلة للضبط ضمن حدود آمنة للمسح.

## 5) قواعد اللغة والاتجاه

1. **الأصل في هيكل الورقة إنجليزي LTR:** أرقام الأسئلة أرقام غربية (1, 2, 3) دائماً، واتجاه الشبكة من اليسار لليمين، وتحذير الطباعة بالإنجليزية (مع سطر عربي عند اختيار قالب عربي).
2. **حروف الفقاعات** قابلة للتبديل إلى العربية دون تغيير اتجاه الشبكة.
3. **تسميات الحقول** (الاسم، رقم الطالب، الشعبة وغيرها) نص حر بأي لغة، وTypst يتكفل بتشكيل العربية الصحيح.
4. ما يعبيه الطالب بخط اليد لا يعنينا لغوياً، الماسح لا يقرأه.

## 6) قواعد وقيود

- الماسح يقرأ أي `bubbleGrid` بشكل عام: كل عمود في الشبكة يمثل خانة واحدة، فلا كود خاصاً لكل حقل.
- تحذير مساحة موثق للمستخدم: حقل اسم بالتظليل يستهلك مساحة كبيرة (26 صفاً للاتينية، 28 للعربية لكل خانة)، والواجهة تحسب وترفض التركيبات التي لا تتسع في الورقة (دالة `fits(spec)` في نفس الحزمة).
- عند عدم اتساع الأسئلة في صفحة واحدة بالتركيبة المختارة، تُرفض التركيبة برسالة واضحة بدل توليد ورقة مشوهة. دعم تعدد الصفحات قرار مؤجل خارج الـMVP.
- كل الإحداثيات دوال من الـspec بالمليمتر. لا قيمة ثابتة في المولّد أو الماسح خارج هذه الحزمة.

## 7) مقارنة مع ZipGrade وتغييرات معلّقة

> مرجع: لقطات منشئ الأوراق المخصصة في ZipGrade (5 خطوات). استُلمت الخطوات 1 إلى 3، والخطوتان الباقيتان قيد الانتظار.
> **حالة هذا القسم: تحليل معتمد لم يُطبَّق بعد على السكيما.** التطبيق يتم دفعة واحدة بعد استلام الخطوات كلها، تفادياً لتعديل السكيما مرتين.

### ما يفعله ZipGrade في كل خطوة

| الخطوة | المحتوى                                                                                                                |
| ------ | ---------------------------------------------------------------------------------------------------------------------- |
| 1      | اسم الورقة (فريد ووصفي)                                                                                                |
| 2      | حقول الترويسة: 6 خانات ثابتة (Name, Quiz, Class, Other 1-3)، لكل واحدة: تفعيل، تسمية معروضة، وعرض (Small/Medium/Large) |
| 3      | هوية الطالب (تفعيل + عدد الخانات + تسمية) ونسخة المفتاح (تفعيل + مجموعة الرموز مثل `ABCD` + تسمية)                     |
| 4، 5   | بانتظار المستخدم                                                                                                       |

### الفروق الجوهرية (مرتبة بالأهمية)

1. **نسخة المفتاح حقل مظلَّل على الورقة، لا خاصية في القالب. هذا أهم فرق.**
   - نموذجنا الحالي: `formCode` داخل المواصفة، فكل نسخة (A, B, C, D) تحتاج **قالباً وPDF منفصلاً**، والمعلم يطبع أربع رزم ويحرص ألا تختلط.
   - نموذج ZipGrade: **ورقة واحدة تُطبع مرة واحدة**، وفيها عمود فقاعات يُظلَّل فيه أي نسخة. الماسح يقرأ النسخة من الورقة ويختار مفتاح الإجابة المطابق.
   - نموذج ZipGrade أفضل عملياً بوضوح، وسنتبناه. `formCode` ينتقل من المواصفة إلى **نتيجة المسح**.

2. **الاستخدام (Usage) منفصل عن التسمية المعروضة.**
   - عندهم: الخانة تعرف دلالياً أنها «الاسم» أو «الشعبة»، والتسمية المطبوعة نص حر منفصل.
   - عندنا: `id` نص حر فقط، فالنظام لا يعرف أي حقل هو اسم الطالب.
   - يهم فعلاً: ربط المسح بسجل الطالب، وترويسات ملف Excel، وتسمية الأعمدة في اللوحة. سنضيف `usage` كحقل دلالي مستقل عن `label`.

3. **العرض قائمة محددة لا مليمترات حرة.**
   - عندنا `widthMm` من 20 إلى 120، وهذا يسمح بحالات قبيحة ويحمّل المعلم قراراً لا يعنيه.
   - سنستبدله بـ`width: 'small' | 'medium' | 'large'` تُترجم داخلياً لمليمترات.

4. **مجموعة رموز حرة لشبكات الفقاعات.**
   - عندهم يكتب المستخدم `ABCD` نصاً، فيقرر الرموز بنفسه.
   - عندنا `alphabet` محصور في ثلاثة (digits, latin, arabic).
   - سنسمح بمجموعة رموز مخصصة إضافة للثلاثة الجاهزة. هذا وحده يغطي نسخة المفتاح دون حالة خاصة.

5. **اسم الورقة غير موجود عندنا.**
   - `title` هو العنوان **المطبوع** عمودياً على الورقة، وليس اسم القالب في اللوحة. حقلان مختلفان بغرضين مختلفين. سنضيف `name`.

6. **دورة حياة للقالب (Status).**
   - عندهم للورقة حالة، والقائمة تقول «No Custom Sheets Published». مسودة مقابل منشور.
   - يهمنا لسبب صارم: **قالب طُبعت منه أوراق لا يجوز تعديله أبداً**، وإلا صارت الأوراق في يد الطلاب لا تطابق ما يقرؤه الماسح. النشر يجمّد المواصفة، وأي تغيير بعده ينشئ نسخة جديدة.

7. **تحذير مشاركة التعريف، وهو تحذير معماري لا تنظيمي.**
   - نصهم: لا تشارك نسخاً ورقية من نموذج مخصص دون مشاركة تعريف النموذج معها.
   - يكشف قيداً في تصميمهم وفي تصميمنا: **الورقة المطبوعة لا تكفي وحدها لقراءتها.** الـQR عندنا يحمل `templateId` فقط، فلو مسحها معلم آخر على جهاز آخر بلا القالب، فشل المسح.
   - **قرار مفتوح يحتاج بتّاً:** هل يحمل الـQR مواصفة مضغوطة كاملة (فتصير الورقة مكتفية بذاتها وتُقرأ بلا شبكة وبلا حساب)، أم نكتفي بمعرّف مع مشاركة القالب؟ الأول أقوى بكثير لمنتج أوفلاين أولاً، وكلفته حجم أكبر للـQR. يُحسم عند بناء `core-omr`.

8. **تصدير PNG للتضمين** إضافة لـPDF، ليضع المعلم الورقة داخل ملف الاختبار نفسه. سهل عندنا لأن Typst يخرج SVG وPNG أصلاً.

### تفاصيل الخطوة 4: تعريف الأسئلة

جدول الأسئلة أعمدته: **Number | Type | Labels | مربع اختيار**، مع مربع اختيار في الترويسة (تحديد الكل) وزر **Remove Selected** لحذف المحدد. الحالة الفارغة: «No questions defined yet».

خمسة أزرار إضافة:

1. `Add multiple-choice questions`
2. `Add multiple-choice questions with alternating answer labels`
3. `Add verbose label questions`
4. `Add numeric entry questions`
5. `Add short response questions`

نافذة «إضافة أسئلة اختيار من متعدد» فيها ثلاثة حقول:

- **Question Type:** `Internal Label` أو `External Label`.
- **Number of Questions:** قائمة منسدلة.
- **Answer Labels:** نص حر بلا مسافات. نص المساعدة عندهم: «مثلاً ABCDE أو TF. حتى 10 أحرف».

### الفروق الجوهرية الإضافية من الخطوة 4

9. **الأسئلة قائمة غير متجانسة، لا عدد.** هذا أكبر تغيير على السكيما.
   - عندنا: `questions: number` و`choices: number` و`choiceLabels`، أي **كل الأسئلة متطابقة**.
   - عندهم: `Question[]`، لكل سؤال نوعه ومجموعة رموزه. فالسؤال 1 قد يكون `ABCDE` والسؤال 2 `TF` في نفس الورقة.
   - النتيجة العملية: ورقة واحدة تخدم اختباراً فيه اختيار من متعدد وصح/خطأ معاً، وهذا شائع جداً في اختبارات المدارس.
   - **مطمئن معمارياً:** تجريدة `bubbleGroups` عندنا تنجو كما هي، لأن المجموعة أصلاً «فقاعات يُظلَّل منها واحدة، كل فقاعة تحمل رمزها». محرك التخطيط وحده هو ما يحتاج دعم صفوف مختلفة الأطوال.

10. **التسمية داخل الفقاعة أو خارجها، وهذا يغيّر الهندسة لا الشكل فقط.**
    - `Internal Label`: الحرف داخل الفقاعة، الصف مضغوط (`1 ⒶⒷⒸⒹⒺ`). هذا تصميمنا الحالي.
    - `External Label`: الحرف بجانب الفقاعة (`1 A○ B○ C○ D○ E○`)، والصف يصير أعرض بنحو الضعف.
    - الخارجي أوضح للطالب وأسهل قراءة، والداخلي أكثف. خيار حقيقي للمعلم لا زخرفة.

11. **حتى 10 خيارات للسؤال.** عندنا الحد 6. سنرفعه إلى 10، وحروف الفقاعات العربية تحتاج توسيعاً مقابلاً.

12. **حجم الورقة متغير، والأوراق الصغيرة تُرصف عدة نسخ في الصفحة.**
    - في معاينتهم: 100 سؤال بتسمية داخلية يعطي `Max. # per page: 1`، و10 أسئلة بتسمية خارجية يعطي `Max. # per page: 4`.
    - أي أن ورقة اختبار قصير تُطبع **أربع نسخ في صفحة A4 واحدة** ثم تُقص. توفير ورق حقيقي للاختبارات القصيرة، وهي الأكثر تكراراً عند المعلم.
    - عندنا الورقة دائماً صفحة كاملة. هذه ميزة تستحق التبني، وتعني أن `paper` لم يعد يساوي حجم الورقة بل حجم **الصفحة المطبوعة**، وأن الورقة نفسها لها مقاس مستقل.

13. **ترويسة تتكيف مع عرض الورقة.** في الورقة العريضة تصطف الحقول أفقياً، وفي الورقة الربعية تتكدس رأسياً. محرك التخطيط عندنا يلفّ الحقول أصلاً، فهذا مدعوم.

14. **علامات تسجيل أكثر في الورقة الكثيفة.** معاينة الـ100 سؤال تُظهر مربعات سوداء إضافية في منتصف الحافتين وأسفل الترويسة، لا أربعة أركان فقط. منطقي: كلما زادت كثافة الشبكة زادت الحاجة لنقاط مرجع وسيطة تقاوم انحناء الورق. يُدرس عند بناء `core-omr` على صور حقيقية.

15. **لا يوجد QR في أوراقهم إطلاقاً.** يطبعون على الحافة اليمنى اسم القالب ورقمه نصاً: `ruh8-ib-mgrs (3070)`. هذا يفسّر تحذيرهم بمشاركة تعريف النموذج: الورقة تحمل معرّفاً فقط، والتعريف يعيش في الحساب.
    - قرارنا يبقى الـQR لأنه يُقرأ آلياً، لكن **نضيف المعرّف مقروءاً للبشر أيضاً** على الحافة، فيعرف المعلم أي قالب بيده دون جهاز.

16. **أنواع أسئلة خارج نطاقنا الحالي**، مسجَّلة للدراسة:
    - `numeric entry`: شبكة أرقام لإجابة رقمية (مثل شبكة الهوية لكن لكل سؤال). مفيدة للرياضيات.
    - `short response`: صندوق كتابة يصححه المعلم يدوياً، لا يقرؤه الماسح.
    - `verbose label`: تسميات كلمات لا أحرف.
    - `alternating answer labels`: تبديل مجموعة الرموز بين الصفوف.
    - **قرار مبدئي:** الاختيار من متعدد بنوعيه (داخلي وخارجي) داخل الـMVP، والأربعة الباقية خارجه مع إبقاء السكيما قابلة لاستيعابها (حقل `type` في السؤال من اليوم الأول).
