# خادم التطبيق: التشغيل والنشر داخل الـVPC

> الشيفرة في `apps/server`: نقاط المصادقة كاملة على `node:http` **بلا أي تبعية خارجية**،
> بقرار لا سهواً، فكل تبعية هنا تجلس على أكثر مسار مهاجَم في المنتج.
> آخر تحديث: 2026-08-22.

## 1) ما يقدمه الخادم

| النقطة               | الفعل                                                                                                                                       |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `POST /auth/signup`  | تسجيل: فحص كلمة السر (ومنها فحص التسريب)، وكتابة المؤسسة والملف والموافقتين والبصمة، وإصدار رمز تأكيد البريد وإرسال رسالته **بلغة التسجيل** |
| `POST /auth/login`   | دخول بالتأخير المتصاعد، ويعيد رمز وصول (15 دقيقة) ورمز تحديث دوار (30 يوماً)                                                                |
| `POST /auth/refresh` | تدوير رمز التحديث، وكشف إعادة الاستخدام يقتل العائلة                                                                                        |
| `POST /auth/signout` | إنهاء الجلسة، و204 دائماً حتى لا يصير الخروج أداة فحص رموز مسروقة                                                                           |
| `POST /auth/confirm` | تأكيد البريد برمز الرسالة، بلا حرق عند أول نقرة (ماسحات البريد تنقر قبل البشر)                                                              |
| `GET /me`            | ملف صاحب الرمز، عبر التحقق ثم `set_config` و`SET ROLE` أي عبر العزل نفسه                                                                    |
| `POST /sync/push`    | دفعة الجهاز: قوالب واختبارات ومفاتيح وطلاب ومسوح وعداد، بمفتاح تعاطف (id الجهاز) وLWW بطابعه، حتى 100 مسح                                   |
| `GET /sync/pull`     | السحب التفاضلي `?after=cursor` على ساعة الخادم وحدها، والمؤشر يتأخر نافذة أمان فلا يُفقد التزام متأخر أبداً                                 |
| `GET /health`        | فحص جاهزية يسأل القاعدة                                                                                                                     |

**القبعتان:** عمليات المصادقة تلبس دور `tc_auth` (مهاجرة `0006`)، وقراءة بيانات المستأجر
تلبس `authenticated` بادعاءات الرمز الموثَّق. ولا قبعة تبقى بعد معاملتها.

## 2) متغيرات البيئة

| المتغير                                          | معناه                                                                                                                  |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| `PGHOST` `PGDATABASE` `PGUSER` `PGPASSWORD`      | اتصال القاعدة، والمستخدم هو **`tc_app`** أبداً لا `tc_owner`، و`assertUnprivileged` يرفض الإقلاع بغيره                 |
| `PGPORT` `PGSSL` `PGPOOLED`                      | اختيارية كما في `packages/db/src/connect.ts`                                                                           |
| `AUTH_KEY_ID` و`AUTH_PRIVATE_KEY`                | هوية مفتاح التوقيع ومفتاح Ed25519 الخاص (base64 لـPKCS8 DER)، يولّدهما `pnpm --filter @transferchecker/server keygen`  |
| `AUTH_RETIRED_KEYS`                              | اختياري، JSON من `kid` إلى المفتاح العام (SPKI base64) للمفاتيح المتقاعدة أثناء التدوير                                |
| `PUBLIC_ORIGIN`                                  | أصل روابط تأكيد البريد، مثل `https://app.example.sa`                                                                   |
| `POLICY_PRIVACY_VERSION` و`POLICY_TERMS_VERSION` | نسختا الوثيقتين الحيتان بصيغة التاريخ، والتسجيل يرفض ما سواهما                                                         |
| `PORT`                                           | افتراضه 8080                                                                                                           |
| `HIBP`                                           | `off` لتعطيل فحص التسريب في بيئة لا تصل الإنترنت، وسقوط الخدمة نفسها لا يوقف تسجيلاً (يفشل مفتوحاً وقاعدة الطول قائمة) |

**تدوير المفاتيح:** ولّد زوجاً جديداً بـ`keygen`، وضع العام القديم في `AUTH_RETIRED_KEYS`،
وبدّل `AUTH_KEY_ID` و`AUTH_PRIVATE_KEY` بالجديد، وأعد التشغيل. بعد 16 دقيقة (عمر الرمز
مع السماحية) يُحذف القديم من المتقاعدة. كل نحو تسعين يوماً، وفوراً عند أي شبهة.

## 3) النشر على SCCC داخل الـVPC، خطوة خطوة

> **ومتى يُنشر:** حين يوجد من ينادي الخادم، أي تطبيق جوال جاهز للمزامنة أو
> بيتا بمستخدمين حقيقيين، ومعهما قرار مزود البريد. اليوم لا شيء يناديه
> (لا جوال، ولوحة التحكم مولّد ثابت لا يقرأ منه)، **وجهاز يعمل على مدار
> الساعة كلفة شهرية بلا مقابل**. أما الخطوتان 1 و2 و4 فمستقلة عن النشر
> وتستحق وحدها: **تطبيق المهاجرات المعلقة يحتاج جهازاً على قائمة السماح
> لا خادماً منشوراً**، ويتبعه `verify` وتشغيلة دخان واحدة ثم إطفاء.

1. **أنشئ ECS صغيرة في نفس الـVPC ونفس المنطقة** التي فيها ApsaraDB RDS
   (me-central-1، الرياض). بهذا يصير اتصال القاعدة داخلياً وينتهي احتكاك قائمة السماح.
2. **أضف العنوان الداخلي للـECS إلى قائمة سماح RDS** (المجموعة الأمنية أو whitelist
   في كونسول RDS). العنوان الداخلي ثابت، بخلاف المنزلي الذي كان يتغير ويعيد العطل.
3. **ثبّت Node 24 وpnpm 11** على الجهاز، واستنسخ المستودع، و`pnpm install`.
4. **طبّق المهاجرات المعلقة أولاً** (من هذا الجهاز نفسه، فهو الآن على قائمة السماح)
   ببيانات `tc_owner`:
   `pnpm --filter @transferchecker/db migrate` ثم **`verify` فوراً**.
   المهاجرات المعلقة أربع (`0004` إلى `0007`)، و`0006` تمنح `tc_auth` لدور `tc_app` تلقائياً إن وجدته.
5. **ولّد مفتاح التوقيع** بـ`keygen` وضع المخرجات في ملف بيئة لا يدخل المستودع
   (مثلاً `/etc/transferchecker/server.env` بصلاحية 600).
6. **شغّل الخادم ببيانات `tc_app`** (لا `tc_owner`؛ سيرفض الإقلاع بها أصلاً):
   `pnpm --filter @transferchecker/server serve`، وخلف systemd في التشغيل الدائم:

```ini
[Unit]
Description=TransferChecker app server
After=network-online.target

[Service]
EnvironmentFile=/etc/transferchecker/server.env
WorkingDirectory=/opt/transferchecker
ExecStart=/usr/bin/pnpm --filter @transferchecker/server serve
Restart=on-failure
User=transferchecker

[Install]
WantedBy=multi-user.target
```

7. **ضع الخادم خلف موزّع حمل أو بوابة تحمل TLS** (شهادة على النطاق العام)، ووجّه
   `/auth/*` و`/me` و`/health` إليه. تحديد المعدل على الحافة (10 محاولات دخول
   في الدقيقة لكل عنوان بقاعدة الخطة قسم 7) يُضبط هناك، والتأخير المتصاعد في
   القاعدة يحمي تحته.

## 4) ما ينقص عمداً، وأين يُركَّب حين يجهز

- **إرسال البريد:** قرار المزود تجاري عند المالك، **والرسالة نفسها مكتوبة
  ومفحوصة** في `apps/server/src/message.ts`: ثماني لغات، وجزآن نصي وHTML من
  جدول نصوص واحد فلا ينحرف أحدهما، واتجاه كل لغة، وألوان النظام وخطوطه
  مربوطة بـ`docs/design/tokens.css` باختبار. فحين يُحسم القرار، **ملف واحد
  يطبّق `Mailer` وفيه دالة واحدة `send(message)`**، وسطر واحد في `main.ts`
  يبدّل `nullMailer`، **ولا يكتب المزود كلمة واحدة يقرؤها معلم**. وما يبقى
  للمزود إعداداً لا شيفرة: عنوان المرسِل ونطاق موثَّق عنده، وSPF وDKIM
  وDMARC على ذلك النطاق. حتى ذلك الحين يقول الخادم في سجله صراحة إن رسائل
  التأكيد لا تُرسل.
- **إعادة إرسال رسالة التأكيد:** لا نقطة لها اليوم، **وهي الجولة التالية
  متى وُجد مزود**. التخزين يقبلها أصلاً (`beginConfirmation` يستبدل الرمز
  ويقتل القديم)، وإخفاق الإرسال **لا يُسقط التسجيل** بل يُسجَّل سطراً بلا
  عنوان ولا رابط، والمعلم يدخل بحساب غير مؤكَّد فتنتظر المزامنة السحابية
  وحدها. **وحين تُبنى تُطلب برمز وصول** لا ببريد في جسم الطلب، وإلا صارت
  أداة استكشاف عناوين وإغراق صناديق بتوقيع نطاقنا.
- **حذف ومزامنة الحذف:** الخطة لا تذكره والجولة لم تبنه؛ يوم يُبنى يحتاج شواهد قبر (`deleted_at`) ومهاجرة، وهو مسمّى هنا حتى لا يُخترع على عجل.
